# Semantic heading level is a per-instance field; outline correctness is validated, not auto-derived

A heading instance's **semantic level** — the HTML element it emits — is a per-instance `level` field on the heading-emitting components (`intro`, `card`, `hero`), a **third axis** distinct from the two the system already separates: visual *rank* (ADR 0022's size-keyed derived heading styles) and token *naming/rank* (ADR 0027's `--{key}` identity). All three are orthogonal — an `h2` that looks like heading-4, or a `p` carrying heading styling, must both be expressible — so the semantic element cannot be inferred from either the size a heading is styled at or the token it references. It is its own choice, made per instance.

**anticustom does not auto-derive the level.** The exploratory "compute it from `section` + nesting depth" angle is rejected on three grounds: the HTML document-outline algorithm is dead (no browser or assistive tech ever implemented it — `<section>` nesting has *zero* effect on heading semantics; the outline is the literal `h1`–`h6` sequence), the render pipeline is flat and context-free (`render_components` threads no depth to children), and component nesting ≠ outline depth (two stacked `section`s are outline *siblings*, both `h2`, yet a depth-walk reads the second as deeper). Auto-derivation would therefore be both fragile and *presumptuous* — a silently-computed wrong outline that looks authoritative and that the human never sees. The system instead lets the human and per-component defaults set the level and **validates the outcome**, keeping the human in control and informed (the advisory-signal posture, ADR 0007).

**The field.** `level`'s values are the literal emitted tag — `h1`–`h6` and `p` — labelled "Heading 1"…"Heading 6", "Paragraph", so render is a plain `<{level}>`. `p` styles the text as a heading (its heading class/token survives) while keeping it **out of the outline** — rank without level, the payoff of the ADR 0022 decoupling and the honest fix for heading-spam (a twelve-card grid need not emit twelve outline headings). Each component declares its own default in its schema (`intro` `h2`, `card` `h3`, `hero` `h2`). The field sets the tag of the **post-promotion heading element**: in `intro`/`hero`, whichever of eyebrow/title is currently the heading becomes `<{level}>` and the demoted siblings stay `<p>`, so `level` composes with eyebrow-promotion (promotion picks *which* text is the heading; `level` picks *what tag* it is) rather than fighting it.

**The `heading-order` failure state.** Outline correctness is a **layout-tier** check over the whole assembled DOM (so it sees the theme/host `h1` the components deliberately don't emit — which is *why* they default to `h2`/`h3`), with an optional cheap render-tier pre-pass over anticustom's own emitted headings. It flags: (R1) not exactly one `h1`, (R2) a first heading that isn't the `h1`, (R3) a descending skip greater than one level (`h2 → h4`; going back *up* is unrestricted) — precisely axe-core's `page-has-heading-one` + `heading-order`, so no a11y policy is invented. `p`-level instances are absent from the sequence: neither counted nor flagged. Severity is the standard dual tier (CONTEXT **Advisory/Enforced**): advisory and dismissible for human editors, enforced and blocking for the publish gate and AI agents. This ADR *declares* the failure state (rules, layer, severity posture); the checker itself is built by the failure-states effort, and the exact gated cutoffs are that registry's knob.

## Considered Options
- **Auto-derive level from `section`/nesting depth** — rests on the dead outline algorithm and the false nesting-equals-outline assumption, needs new context-threading through the render pipeline, and silently emits authoritative-looking wrong outlines; validation catches the same mistakes while leaving the human in control.
- **Keep hardcoded per-component levels (status quo)** — cannot express a correct outline per page: a `hero` holding the page title can never be `h1`, a deeply-placed `intro` can never drop to `h3`.
- **Couple the element to visual rank / the heading token** — conflates the very axes ADR 0022 and ADR 0027 separated; an `h4`-looking `h2` becomes inexpressible.
- **Only `h1`–`h6`, no `p`** — forces every heading-styled title into the outline, reviving heading-spam and forfeiting the rank-without-level case the decoupling exists to enable.
- **Validate only anticustom's own emitted headings (render-tier, anticustom-scope)** — blind to the theme's `h1`, so it either misses real defects or false-alarms on a perfectly correct `h2`-start; heading order is irreducibly a whole-document property.
- **Enforce-only (block on any bad heading)** — too aggressive for human editors; the dual tier keeps humans informed-but-unblocked while still stopping AI and the gate.

## Consequences
`intro`, `card`, and `hero` gain a `level` enum field (values `h1`–`h6`, `p`) with a per-component default, and their templates replace the hardcoded `<h2>`/`<h3>` with `<{level}>` woven into the existing eyebrow-promotion logic. `heading-order` is registered in the `failure_states` registry as a layout-tier state with rules R1–R3 and the dual-tier severity; its checker implementation rides the failure-states effort (issues #2–#4) and the #38 sequence, not this decision. The system now has three explicit, orthogonal heading axes — **visual style** (ADR 0022, keyed off computed size), **token identity** (ADR 0027, `--{key}`), and **semantic element** (this ADR, the `level` field) — none derivable from another. #44 surfaces no new palette-model tickets; with it resolved, #38 (the implementation sequence) has every decision blocker closed.
