# Scale families are open ordered sets: one anchor pointer, orthogonal spec status

ADR 0017 fenced scale families (spacing, type sizes) out of the open-vocabulary world — structural names, no alias, no freeform additions — reasoning that a scale's names are positional (`s` < `m` < `l`) and renaming would break the math. That fence was a scope boundary, not a considered stance (it surfaced while grilling #37). This ADR removes it: **spacing, text, and headings are open ordered sets like every other family**, adopting ADR 0021's `{ default, sizes }` envelope, presence-is-membership, integer `position`, and slug grammar. The only thing that stays scale-specific is *how values are produced* — a computed ramp (ADR 0018) — not how names, membership, or ordering work.

**One merged anchor pointer, not a base+default pair.** The old model carried a standalone `baseSize` field plus an implicit `m`-at-exponent-0; generalizing it naively produced two pointers — which step is 1.0×, and which step is the fallback. That duality was an artifact of the external `baseSize`, and it dissolves: **there is no `baseSize` field.** A scale family's `default` step carries the sole authored value in scale mode; every other step computes as `defaultValue × scale^(signed ordinal distance from the default in position order)`. The `default` step is simultaneously the exponent origin, the ratio pivot, and the `--space`/`--text` fallback target — because a geometric sequence has no privileged origin, so these were never three independent choices. Moving the pointer is value-preserving (the newly designated step seeds from its current computed value; the ramp does not move) and changes only the bare-alias target — `--space` = the default step's value = the project's base spacing unit. In custom mode the origin/pivot roles go dormant (every step is authored per device, ADR 0018) and the pointer is purely the fallback target.

**Bare aliases and rank-emitted headings.** Spacing and text gain bare `--space` / `--text` aliases and emit vocabulary-named variables (`--space-gutter`), so a pick emits `var(--space-gutter, var(--space))` and a dangling reference degrades to the base unit instead of collapsing to `0` (extending ADR 0015/0017's chained-fallback contract to scale families — the #37 emission rule). **Headings** are open in *membership and labels* but emit **rank-numbered** variables (`--heading-1` … biggest first), because a skin binds them positionally ("style the largest heading") without knowing the project's vocabulary; the label is free (ADR 0023), the variable is the rank. The heading count is a spec choice, not fixed at six — HTML's six semantic levels are the *skin's* element-to-token mapping concern, not a constraint on the type scale. ADR 0022's derived heading styles are untouched: they key off computed px size, never names.

**Spec status is orthogonal to scale membership.** A custom token can ride the scale and receive a computed value (factory `xxs`/`xxl` do). Being a custom token means only that the followed spec doesn't promise its variable and that skins reference it via chained fallback — not that it leaves the ramp or forfeits its computed value. From the editor a custom scale member is indistinguishable from a spec one.

**Value-order cannot silently diverge from key-order under a followed spec** — and the guarantee does not rely on the user seeing keys (token names are hidden by default, ADR 0023). Two locked decisions secure it: (1) the ramp is monotonic by construction (`anchor × ratio^position` is monotonic in position, so display-order = value-order, always), and (2) a *following* site never reorders spec tokens — reorder/rename/insert of keys is a **drafting** act, frozen at publish (ADR 0023). A following site sets values (anchor + ratio, or per-step in custom), relabels, aliases, and adds custom tokens (which it *may* reorder — they are its own). So `--space-xl` stays pinned to the top slot and the math keeps it largest. In custom mode a user can author non-monotonic values, but that is a valid authored state, not a failure — nothing breaks, every variable resolves — so it is **not warned**. "Never fail silently" governs errors and data loss (incomplete stores, dangling `default` pointers — still hard errors), not unconventional-but-valid choices; a live warning would fire transiently mid-edit (you must cross a neighbor before fixing it) and erode advisory credibility.

## Considered Options
- **Explicit per-step exponent** (each step stores its own power) — a second ordering-like number that can silently disagree with `position`, scrambling the ramp; the ordinal model keeps scale mode's two-knob promise.
- **Separate base + default pointers** — preserves a decoupling (fallback rung ≠ ratio pivot) that has *zero* effect on the reachable set of ramps (geometric sequences have no privileged origin): pure cost, no capability.
- **Keep `baseSize` as an axis field** — the source of the base-vs-default duality; folding it onto the default step removes the phantom second pointer.
- **Fixed six structural headings** — conflates HTML's six semantic levels with the heading *type scale*; the consumer is the skin/spec (ADR 0023), which can promise three heading tokens or twelve.
- **Vocabulary-named heading variables** (`--heading-display`) — forces skins to know project vocabulary; rank-numbering is the portable contract, labels stay free.
- **Warn on non-monotonic custom values** — fires transiently during normal sequential editing, training warning-blindness; no downstream consequence comparable to illegibility; its premise (an "intended order") is exactly what custom mode discards.
- **Auto-sort or forbid reorder to enforce monotonicity** — fights ADR 0021's uniform reorderable envelope and overrides a legitimate choice; monotonicity is already guaranteed for spec tokens by freezing.

## Consequences
`generate.php` drops the hardcoded `$spacePositions` / `$textPositions` / `$headingPositions` maps and the `baseSize` reads; it sorts by `position`, reads `sizes[default]` as the anchor, computes `anchor × scale^ordinal` per step, and emits bare `--space` / `--text` aliases plus rank-resolved `--heading-{n}`. `defaults.json` migrates: `baseSize` folds onto the default step's value, `scale` becomes a per-device pair (ADR 0018), `override` flags are dropped, `text.m`'s pin folds into the scale, and `xxs` / `xxl` persist as custom-token members with `position`s. Verify keeps the incomplete-store and `default`-integrity errors and gains no non-monotonicity check. `panel.js` renders each scale family as an ordered ramp — drag-reorder for owned tokens, frozen for followed spec tokens; a mode toggle; in scale mode the anchor step editable with others computed-read-only; in custom mode all editable. The base spec (ADR 0023) is unchanged in surface; this ADR defines the group model it references. A follow-on decides how naming *conventions* (t-shirt / ordinal / descriptive / Tailwind-steps — all already expressible) are offered.

## Amends
ADR 0017's scale-family exclusion (no alias, no freeform names, no chained fallback) is withdrawn: scale families are open sets with bare aliases and chained fallbacks like pick-one families. ADR 0021's envelope and rules extend to spacing, text, and headings.
