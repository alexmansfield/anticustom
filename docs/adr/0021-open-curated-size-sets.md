# Size options are open curated sets: validated values, positional order, presence-is-membership

The pick-one families' option sets open up (the dossier #25 amendment): membership is a stored fact, users create, rename, and remove options, and removal discards customization while re-adding seeds from the schema's catalog. Radius `full` becomes an **ordinary editable option** — amending ADR 0017's fixed-name carve-out — because a guaranteed-but-invisible constant reads as a missing size in the editor, and users would recreate it by hand. Its component references migrate to the standard chained fallback (`var(--radius-full, var(--radius))`) like every freeform name: delete `full` and pills degrade to the default radius, by contract.

Free values are validated, not trusted: `generate.php` raw-interpolates into CSS, so every stored value must pass a **single-token anchored grammar** in the `fields/sanitize.php` spirit — `0`, or a nonnegative decimal with an optional unit from `px rem em vw vh vmin vmax ch` (radius additionally accepts `%`; borders are `<length>`-only since percentage border-width is invalid CSS and should fail at authoring time, not silently in the browser). Unitless input is **normalized to `px` at save time**, so users who don't know units never type one, yet stored data is always a canonical CSS value — the leniency lives at the door, never inside the data. No `calc()`, no `var()`, no negatives. Shadows stay structured numerics (`x`/`y`/`blur`/`spread`/`opacity`) entirely outside this grammar. Option names follow the color-system-spec §2d slug rule (`/^[a-z0-9-]+$/`).

Ordering is an explicit **integer `position` per option** — the pattern headings and text sizes already use — replacing the generator's hardcoded `$radiusOrder`/`$borderOrder`/`$shadowOrder`. The generator sorts by it; the editor renumbers the whole family on reorder or insert (sets are tiny); a new size appends at `max+1` unless placed. Schema-known and user-created sizes are indistinguishable in ordering, which is the point of an open set. `position` is internal bookkeeping: users experience ordering as list order and drag to change it.

The three families converge on one envelope: `{ "default": <name>, "sizes": { <name>: { "position": <int>, …payload } } }` — only the payload differs (a CSS string `value` for borders/radius, structured parts for shadows). **`enabled` dies: presence in data is membership**, the direct mirror of ADR 0015's sparse palettes; an `enabled: false` entry is the "exists but off" third state the dossier amendment already rejected. Borders' unread `defaultSize` becomes the read `default`; shadows gain the missing wrapper and a default. Lifecycle: **`default` naming a missing key is a hard verify/generate error** — the editor deletes-with-reassign atomically, and nothing auto-reassigns. Deleting the last option is impossible for free, because the last option is necessarily the default. The editor rule ADR 0017 set stands and gains its label: a single-option family renders one field labeled by family name ("Border") with no size-name input; names surface when a second option arrives, because size names are comparative vocabulary that carries no meaning in a set of one.

## Considered Options
- **`--radius-full` as a generator constant outside the data** — cleanest as type theory (every pill value renders identically, editing buys nothing), but an empty spot in the editor teaches "not supported," not "guaranteed elsewhere"; data that exists to be seen has different rules than data that exists to be consumed.
- **`calc()` in the grammar** — unparseable by an anchored regex (nesting, comments, embedded `var()`); admitting it means a real tokenizer and reopens the injection surface the grammar exists to close. Computed values can be typed as results.
- **Store bare numbers, generator appends `px`** — "bare means px" becomes an implicit contract every consumer must re-know (generator, explorer panel, antipress after sync); exactly the kind of unstated rule that rots.
- **JSON key order as the ordering** — free in PHP (`json_decode` preserves order) but JavaScript iterates integer-like keys first, always: a size legally named `2` would silently teleport to the top in `panel.js` while the generator kept authored order.
- **Keeping `enabled` flags** — quietly resurrects the third state the membership decision killed; verify and the panel would carry corpses forever.
- **Silent default reassignment on delete** (first-by-position) — the bare alias backs real component CSS; which option backs it is a design decision, and quiet fallbacks are what ADR 0018 ruled out for incomplete stores.

## Consequences
`generate.php` drops the three hardcoded order arrays, the `enabled` skips, and the vestigial unit ternary (`generate.php:284`); it sorts by `position`, emits stored value strings verbatim (pre-validated), and reads `default` to emit the bare alias. The sanitizer gains the size-value grammar and save-time `px` normalization alongside the slug rule. `defaults.json` migrates: values become CSS strings, `enabled: false` entries are deleted, each family curates at least one member with a designated `default` (the lifecycle makes empty families unrepresentable), and the schema retains the known-size catalog as re-add seeds. Verify gains the default-pointer integrity check. `panel.js` gains the `count === 1` family-label collapse and the delete-with-reassign flow.
