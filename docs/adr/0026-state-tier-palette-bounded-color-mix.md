# Interaction states live at the palette tier as generator-authored `color-mix()`; the ramp carries none

ADR 0025 made the ramp tier **unconditionally dense** (`colors × stops`, no `enabled`, no holes) because `tokens.css` is an open surface whose references can't be enumerated, and it booked the remaining bounding work explicitly: *"all 'keep `tokens.css` bounded' work moves to the state tier (issue #39), whose old 'enabled-flags + sparse emission' premise this ADR rewrites to 'presence-is-membership emission, bounded at the state tier.'"* This ADR discharges that debt. The spec §5 "variable count" worry — `directions × shades × (base/hover/active)` ballooning as colors grow — is answered not by gating the ramp but by moving interaction states off it entirely.

**The gate: interaction states emit only at the palette tier.** Raw ramp stops carry a base value and nothing else — no `--{color}-{stop}-hover`, no `-active`. The `-hover`/`-active` variables emit only for **palette-tier tokens** (the contrast-scale steps of ADR 0015 and the intents of ADR 0016/0020). This is the principled mirror of ADR 0025's density: the ramp is dense *because* its consumers are external and unenumerable; the state tier is *gated* because its only consumers — palettes and intents — live in the same token data the generator reads, a **closed internal set**. The emitted state count is therefore `(palette tokens) × 2`, a function of the spec-declared palette, **independent of how large the ramp grows**. This subsumes the weaker "emit `-hover` only for stops something references" option the ticket floated: the only things that reference interaction states *are* palette tokens, so the tier rule *is* the reference gate, with no per-stop reference index to build. The evidence bears this out — across the whole component library the interaction-state references are a handful, and every one is a palette-tier token (`hard-contrast`, `base`), never a raw ramp stop.

**The vehicle: generator-authored `color-mix()` expressions.** A palette token's state is emitted as a mix off the resolved role color, authored by the generator:

```css
--palette-accent:        var(--primary);
--palette-accent-hover:  color-mix(in srgb, var(--palette-accent), black 12%);
--palette-accent-active: color-mix(in srgb, var(--palette-accent), black 20%);
```

The generator picks the **mix target** (a light or dark pole) and the **percentage** per token from the role's resolved lightness. This buys three properties a fixed component-side overlay cannot: the direction is **color-aware** (a static `color-mix()` in component CSS commits to one direction for every color it touches — pure CSS can't branch on the base's lightness; only the generator, which holds the resolved color, can decide); the value is **cascade-live** (it references `var(--palette-accent)`, so a runtime re-point of the role flows through — more faithful than a frozen literal `#2b6cb0` or a stepped `var(--primary-600)`, which follow neither the role); and mixing **`in srgb`** is a lerp toward an sRGB-cube corner, so it stays in gamut without asking the browser to gamut-map — consistent with the OKLCH-generation finding (issue #29) that the generator owns gamut.

**Direction is coarse here, fine-tuning is a separate effort.** The generator applies one coarse principle when it authors the mix: shift *outward* — toward the fill's own extreme, away from its foreground — to increase contrast; if that would breach a chroma floor (mixing a dark color further toward black desaturates it), reverse by the same small amount instead. Because the mix is small and bounded, the reversal never crosses the tonal middle, so it can't strand light foreground text on a suddenly-light fill — the failure mode that kills any *quantized* two-step scheme. The exact pole-selection thresholds, mix magnitudes, and chroma-floor value are the **state-derivation open questions** already scoped out of this map (spec §3b/§5); `color-mix()` gives them a cleaner home (the "band-boundary discontinuity" question dissolves — there are no bands), but this ADR does not settle them. It fixes the *gate* and the *vehicle*, not the tuning.

**`hover` and `active` are two tokens; active is a slightly larger mix.** The cross-system norm is distinct-but-small: Radix assigns step 4 to hover and step 5 to pressed, Bootstrap darkens hover ≈15% and active ≈20%, Material 3 layers 8% for hover and 10% for pressed. Active is a *hair* stronger than hover in the same direction — never a wildly different color. Emitting both names (active a larger `%`) costs one extra bounded row per role and gives component CSS a natural `:active { … -active }` hook; the large "pressed" cues (ring, inset, scale) are **structural** and belong to the component, not to token generation. This is why active being distinct reintroduces no overshoot: it is a marginally larger mix, not a second discrete stop.

## Considered Options
- **Per-ramp-stop states (status quo)** — `generate.php` emits `-hover`/`-active` for every shade of every color (`:359–370`), tripling a now-dense open ramp to feed consumers that only ever touch the palette tier. Unbounded as colors grow; the exact balloon spec §5 warned about.
- **Quantized ramp stepping** (`--palette-accent-hover: var(--primary-600)`) — cascade-ish and computation-free, but cannot degrade at the extremes: stepping outward hits the achromatic endpoint (chroma fail), and reversing inward by a full second stop crosses the tonal middle into a light shade, stranding light foreground text (contrast fail). Coarse quantization has no safe landing near the ends.
- **Frozen computed literal** (`--palette-accent-hover: #2b6cb0`) — safe direction, but not cascade-live; a downstream re-point of the role doesn't flow through.
- **Fixed component-side overlay** (Material-style `color-mix()` in component CSS, no state tokens) — the tightest possible bound (`palette × 0`), but a static overlay can't branch direction on the base color; the only auto-adaptive fixed overlay mixes toward the on-color, which nudges the fill *toward* its text (dimming), the opposite of the intensify-for-contrast direction chosen here. Adaptivity requires a brain, and the component (pure CSS) hasn't one; the generator has.
- **Single interaction token (`hover == active`)** — viable and matches a common hand-authored habit, but the cross-system norm is a distinct-but-small active, and a generator-authored `color-mix()` makes the distinct active nearly free.
- **Verify budget assertion as the gate** — a count guard in `verify.php`. Unnecessary as a *gate*: the tier rule is a structural bound, not a threshold to police. Available later as a belt-and-suspenders sanity check, not load-bearing.

## Consequences
`generate.php` changes: the per-stop state emission (`:359–370`) drops — ramp stops emit base values only; the `colorway_derive_state` variable-chaining (`:155–161`) and the HSL `color_interaction_shifts` band math (`:110–146`) retire for interaction states, since the browser now performs the mix and the generator only *reads* a resolved lightness to choose the mix target and percentage. Palette-tier emission (`:405–411`) rewrites each token's `-hover`/`-active` as a `color-mix(in srgb, var(--palette-{token}), {pole} {n}%)` expression, active a larger `n` than hover. Emitted state count becomes `(palette tokens) × 2`, flat as the ramp grows. Component and skin CSS are **unchanged** — they still reference the stable role names `var(--palette-accent-hover)` and never see the ramp. `-on` is untouched: it stays an authored palette key (ADR 0020), orthogonal to interaction states and not a count driver. The concrete migration commit sequence is issue #38. CONTEXT gains the term **State tier**; **Pin** and **Ramp** are amended.

## Amends
- **ADR 0019 (and the CONTEXT term _Pin_)** — the clause "states (`-hover`/`-active`) derive from the pinned value through the normal band logic" no longer holds: the ramp, pinned or not, carries **no** state variables. A pin flows into an interaction state only when a palette token *references* that stop, and then through the palette-tier `color-mix()` off the resolved (pinned) value — not through stop-level band logic.
- **ADR 0025** — discharges its booked "bounded at the state tier (issue #39)" debt with the concrete mechanism: palette-tier-only emission via generator-authored `color-mix()`.
- **Out-of-scope note (state-derivation open questions, spec §3b/§5)** — reshaped, not resolved: the `color-mix()` vehicle dissolves the "band-boundary discontinuity" sub-question and re-poses "mid-tone direction" and "clamp-vs-flip" as "which pole, how much, and where the chroma floor sits." Still a future effort; this ADR fixes only the gate and the vehicle.
