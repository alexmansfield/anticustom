# Scale mode derives heading styles from computed size: leading over em, no per-level authoring

Dossier #25 item 9 gave scale-mode headings a **single global style block** — one line-height/letter-spacing/weight for h1–h6. Prototyped against real hierarchies, that flattening makes out-of-the-box typography worse than today's per-level defaults, so the item is rejected — but so is retaining six authored blocks in scale mode, which contradicts the mode's premise (ADR 0018: systematic, two numbers, retunable). The resolution: scale mode **derives** heading styles from each level's computed size, the way it already derives the sizes themselves.

Line-height is `calc(1em + <leading>)` — the text's own size plus a fixed authored increment (**leading**, a px length; factory default `8px`, tuned by eye in the #34 prototype). The slope is a constant `1em`, not a second knob. Because line-height is affine in font size, the industry curve falls out automatically — small headings loose (h6 ≈ 1.5, at body copy's ratio), display sizes tight (h1 ≈ 1.05–1.15 depending on scale) — and it stays correct when the type scale itself is retuned, which is the scenario that killed every level-keyed alternative: a formula keyed to *level* hands h1 its tightest value whether h1 computes to 49px or 177px.

The slope unit is **`em`, not `ex`** — the fork ACSS v4's Smart Line Height (`calc(leading + 2ex)`) put on the table. `ex` reads the loaded font's real x-height, so line-height would self-adjust on font swaps; but its resolved value exists only in the browser — PHP (`generate.php`, `verify.php`) can never know it, the explorer's token table can't print it, and the synced output ships unknowable numbers. That trade repeats the fork ADR 0020 already settled for `-on` colors: authored-and-verifiable beats runtime-clever. What `ex` buys is ~2–3px at mid sizes across real-world x-heights (0.45–0.55em), and a font swap already demands an eyeball pass (letter-spacing and weight don't self-adjust under any model) — the user adjusts leading against the live preview, the same loop that produced the factory default. With a `1em` slope the formula's floor is `1em + leading`, so no clipping guard (`max(1.1em, …)`) is needed; that was `ex`-pathology insurance.

Letter-spacing derives through the same affine shape, `calc(<slope>em + <constant>px)` — it needs both terms because it crosses zero (a multiplicative rule can't produce nonzero from zero). Factory defaults `-0.022em + 0.35px` reproduce today's endpoints (≈ 0 at 16px, −0.02em at 177px). Weight does not interpolate; scale mode carries a **single authored weight** for all levels (factory default `600`) — today's 700-at-h1/h2 stepping is expressible only in custom mode. Custom mode (ADR 0018) is untouched: per-level style blocks live there, and the switch-to-custom seeding contract extends naturally — style fields seed from the formulas' current computed values, exactly as sizes seed from the scale computation. The `typography.text` axis is out of scope: its flat authored line-height stands; adopting the derived model there is a future decision.

The generator emits the `calc()` forms rather than pre-resolved per-level numbers: under ADR 0018's per-device anchors the computed size is fluid, and the `em` term tracks it for free — while remaining exactly evaluable server-side at any anchor for verify.

## Considered Options
- **Single static global block (dossier item 9 as written)** — one line-height across a 16px→177px run is visibly wrong at one end or both; prototype round 1 killed it on sight.
- **Per-level blocks retained in scale mode** — twelve authored fields to maintain, and today's six values turn out to lie on a two-parameter curve anyway; authoring samples of a formula is busywork the formula replaces.
- **Two-anchor interpolation (author h1 and h6, interpolate between)** — reproduces today's values with four fields, but anchoring on endpoints is grammar found nowhere else in the system.
- **Level-keyed ratio (`lh = base × ratio^position`, the size grammar)** — reads beautifully in the editor but is blind to computed px; retune the type scale and every value is stale. Scale mode exists to retune the scale.
- **`ex` slope (ACSS Smart Line Height)** — font-metric awareness at the cost of a schema that never knows its own output; see above.
- **`max(1.1em, …)` floor** — meaningful only under `ex`, where a small-x-height font could bottom out near 0.88em; with a `1em` slope the formula cannot clip.

## Consequences
`styles/tokens.schema.json` and `defaults.json`: scale-mode heading styles collapse from six per-level blocks to `{ leading, letterSpacingSlope, letterSpacingConstant, weight }` (names to be settled in implementation); the per-level blocks migrate into the custom store per ADR 0018. `generate.php` emits `--heading-{level}-line-height: calc(1em + 8px)` and the letter-spacing calc instead of per-level literals. `verify` gains exact server-side resolution of both formulas at the ADR 0018 device anchors. `panel.js` reshapes the typography tab: scale mode shows the derived knobs (leading as the headline field — it is not the optical gap between lines, and must not be labeled as one; it is added on top of the text's own height), per-level fields appear only in custom mode. Prototype preserved on `prototype/34-heading-typography` (explorer route `?tool=prototype-headings`).
