# Color is two spec-declared tiers: flat open ramp, spec-shaped palette, `enabled` dies

Colors were the last axis still on **locked names and `enabled` flags**: `color.sections.{brand,neutral,semantic}.colors` fixed `primary`/`secondary`/… with per-color `enabled`, and `color.hues` fixed six stop names (`ultra-light`…`ultra-dark`) with `{value, enabled}`. Every sibling family had already moved to open curated sets (ADR 0021: presence-is-membership, `enabled` dies), open scale families (ADR 0024), and the published-spec model (ADR 0023: the spec defines token *names*, sites provide *values*). This ADR brings colors across, and in doing so states plainly what was implicit: **the whole color system is two spec-declared tiers, and anticustom hardcodes neither.**

**Two tiers, both spec-declared; the generator is shape-agnostic.** The spec declares token *shapes*; `generate.php` emits whatever it declares.

- **Ramp tier** — an open set of **source colors** × an open ordered **stop scale**, emitting `--{color}` and `--{color}-{stop}` (`--primary`, `--primary-light`, `--neutral-ultra-dark`). Source colors are **base spec + custom beyond** (ADR 0024's model — spec status is orthogonal to membership; a custom `magenta` rides the same stops and gets its full ramp). The stop scale is an L-ordered rank, spec-declared like every other scale.
- **Palette tier** — the contrast-scale steps (ADR 0015) *and* the intents with their `-on` partners (ADR 0016/0020): `surface`, `soft-contrast`, `hard-contrast`, `accent`/`accent-on`, `success`/`success-on`, …. Their **count and names are a spec choice** — a spec may offer a three-step contrast scale or a five-step one. This makes explicit what ADRs 0015/0016 left as fixed defaults: the palette *shape* is spec vocabulary, not a hardcoded slot list.

**The spec authors emitted names; labels are free; values are the site's.** The emitted variable name is the spec's — a Tailwind-flavored spec emits `--primary-100 … --primary-900`, the anticustom base spec emits `--primary-ultra-light … --primary-ultra-dark`. Headings' rank-numbered `--heading-1` (ADR 0024) was *that spec's* choice, not a universal law; ramp stops carry vocabulary in the emitted name because authors reference `var(--primary-light)` directly and constantly (251 refs today), where `--primary-1` would be a strictly worse surface and would throw away the recognizability a Tailwind user relies on. The **label** is a free project relabel that never touches the emitted name (ADR 0023). The L **values** (90, 80, …) are site/skin-provided, as are the hexes.

**Wiring is skin data, not spec.** The spec fixes each palette slot's *shape*, never *what it points at*. `accent = var(--primary)`, `surface = var(--neutral-ultra-light)` are **skin defaults**, freely rewireable (ADR 0023: spec defines names, sites provide values). Consequently **no source color is forced into the spec roster by the palette** — a lean site may wire its palette to any colors it defines. The base spec's color roster is therefore a lean-default choice, decoupled from the palette shape, not a coupling constraint.

**Groups flatten.** `brand`/`neutral`/`semantic` never entered an emitted variable (the ramp emits `--success`, never `--semantic-success`), so they are pure editor organization. Source colors collapse to **one flat open set**; any grouping survives only as an optional editor tag, not as data structure the generator reads.

**`enabled` dies; the ramp tier is unconditionally dense.** Presence-is-membership: a color that exists, crossed with a stop that exists, **emits** — no `enabled`, no holes. Sparse "emit only what's referenced" is impossible for this tier and this is *forced*, not chosen: `tokens.css` is an **open surface** referenced by consumers outside the generator's view (hand-written component CSS, antisloth, downstream sites, a custom class typing `var(--magenta-300)`), so references cannot be enumerated — and a spec *guarantee* means precisely that a variable is present even when no visible reference exists. The variable count is thus `colors × stops`, predictable and owned by the spec author (anticustom base ~7×6; a Tailwind spec ~11×11). Reference-gating stays possible only where the consumer is **internal** — the **state tier** (`-hover`/`-active`/derived `-on`) is consumed by palettes, which live in the same token data — so all "keep `tokens.css` bounded" work moves to the state tier (issue #39), whose old "enabled-flags + sparse emission" premise this ADR rewrites to "presence-is-membership emission, bounded at the state tier."

## Considered Options
- **Keep locked color/stop names + `enabled`** — leaves colors the sole exception to ADRs 0021/0023/0024; the "different design systems, different terminology" use case (Tailwind steps vs t-shirt vs descriptive) stays unreachable.
- **Rank-numbered ramp stops** (`--primary-1`, mirroring headings' `--heading-n`) — portable, but ramp variables are author-facing and referenced constantly; a mechanical rank is a worse surface than `--primary-100`/`--primary-light` and discards cross-system recognizability. Headings differ because skins bind them positionally and authors rarely reference them raw.
- **Sparse ramp emission (emit only referenced tokens)** — undeterminable: `tokens.css` is an open surface whose references can't be enumerated, and a guarantee that vanishes when unreferenced isn't a guarantee. Only the state tier (internal consumers) can be gated.
- **Hardcode the palette shape in anticustom** — bakes one design system's slot list into the tool; declaring the palette shape *in the spec* is what makes the system broad.
- **Spec fixes the palette→ramp wiring** (`accent` always → `primary`) — forces color names into the spec roster and blocks a lean site from wiring its own colors; wiring belongs to the skin as ordinary values.
- **Keep the brand/neutral/semantic groups** — they carry no emitted meaning; a flat set plus an optional editor tag is the honest shape.

## Consequences
`defaults.json` migrates: `color.sections.{brand,neutral,semantic}` collapse to one flat open source-color set (`{ value: hex, label? }` per color, integer `position`, no `enabled`); `color.hues` becomes a flat ordered **stop scale** (spec-authored names, site-provided L `value`, integer `position`, no `enabled`); spec-vs-custom membership follows ADR 0023/0024 (spec colors/stops are non-deletable rows, custom ones freely added). `generate.php` drops the `enabled` reads and the three-section walk; it iterates the flat color set × the stop scale and emits the dense ramp grid, plus the spec-declared palette slots wired by skin values. `panel.js` loses the enabled toggles and the brand/neutral/semantic split, rendering one color list (add/remove/relabel) and the stop scale as an ordered ramp. Verify keeps value-resolution and `default`-integrity errors; nothing new to warn. The base spec (ADR 0023) is unchanged in surface — this ADR names the two-tier color model it references. The concrete migration commit sequence is issue #38; the state-tier emission bound is issue #39.

## Amends
- **ADR 0015 / 0016** — the palette *shape* (contrast-scale step set, intent set) is spec-declared vocabulary whose count and names are a spec choice, not a fixed slot list; the wiring from a palette slot to a ramp token is skin-provided value, not spec.
- **ADR 0024** — its follow-on note ("a follow-on decides how naming *conventions* are offered") now spans colors: ramp and stop naming conventions are decided alongside the size scales in issue #43, not here. This ticket fixes only that stop names are spec-authored emitted names, not rank-numbered.
