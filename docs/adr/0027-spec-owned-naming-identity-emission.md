# Token naming is spec-owned identity emission; conventions are emergent

**anticustom owns no vocabulary.** A token's key, its display **label**, and its emitted CSS variable are all spec data — the engine imposes no prefix, no rank, no name. This is ADR 0023's "the spec defines token names and their emitted variables" taken to its literal end: there is no second naming authority. A **naming convention** (t-shirt `s/m/l`, ordinal `1/2/3`, descriptive `tight/roomy`, Tailwind-step `100/200/300`) is therefore not a modeled type the system knows — no enum, no picker, no per-family `convention` field — but an *emergent pattern* in whatever keys a spec happens to ship. All four already pass ADR 0021's slug grammar and sort by integer `position` (ADR 0024 decoupled ordering from the key), so feasibility was never the question and nothing needs building to "support" them.

**Emission is identity: the variable is `--{key}`.** The generator applies no family prefix; whatever namespacing a spec wants lives *in the key it authored* — a spacing token keyed `space-m` emits `--space-m`, a heading keyed `h1` emits `--h1`. This sharpens ADR 0023's `spacing.m → --space-m` example: the `space-` is not generator-applied (as `generate.php` currently hardcodes it) but key-embedded, chosen by the spec author to keep the variable globally unique. The **label** is an independent spec-owned display string that may differ from the key (label "M" over key `space-m`); what ADR 0023 forbids is *the engine* manufacturing a label to paper over a key it picked, never a spec choosing one. The "family" a token belongs to (for ramp math, per-device anchors, mode — ADR 0018/0024) is a data grouping that contributes nothing to the name.

**One canonical base spec; variety is drafting.** anticustom ships exactly one base spec (ADR 0023) — t-shirt spacing/text, `h1`–`h6` headings — not a menu of convention variants. A project wanting Tailwind or ordinal *drafts its own spec* (greenfield, or start-from-base then reslug). Switching splits by intent: **relabel** changes the display only (free, non-breaking, available to a following site); **reslug** changes the emitted variable and is therefore a *drafting* act that breaks skins following the old spec. Cross-convention interop leans entirely on ADR 0023 aliasing (a lean site aliases a skin's expected token to its own). No convention widget, and no bulk-reslug helper — auto-mapping one convention onto another would require the system to *know* both, smuggling the rejected enum back in.

**Headings drop rank-emission and become fully symmetric.** ADR 0024 kept one exception — headings emitted rank-numbered `--heading-{n}` so a skin could bind them positionally without knowing the project's vocabulary. That exception is withdrawn: its portability is already provided for every other family by spec-follow + aliasing (a skin follows a heading spec exactly as it follows a spacing spec), so rank-in-the-name was redundant. Headings keep `position` — the ramp needs an ordinal for `anchor × scale^position` — but `position` orders the *math*, never the *name*. So headings emit key-identity like spacing and text; the base spec's `h1`–`h6` are ordinary vocabulary a project may reslug to `display/title/body`.

**Validation guards data loss, not taste.** Because the variable *is* the key, two tokens sharing a key emit one variable and one silently clobbers the other — a real data-loss failure, so a **duplicate key is a hard verify/generate error** (a broken spec). *Mixing* conventions within a family (`space-s, space-m, gutter, 300`) is **not** guarded: every variable resolves, `position` orders them, nothing breaks — unconventional-but-valid, the same category ADR 0024 declined to warn on for non-monotonic custom values. Detecting a "mix" would anyway require classifying each key's convention, i.e. the convention enum this ADR rejects.

## Considered Options
- **Model conventions as a first-class type** (a per-family `convention` enum + picker, optional per-convention validation) — re-erects the closed-vocabulary machinery ADRs 0021/0024 dismantled; the moment the allowed conventions are enumerated the open set is re-fenced, for guided UX that free labels already deliver.
- **Ship a family of base-spec variants** (t-shirt base, Tailwind base, …) — forks the single reference implementation N ways and fragments the skin ecosystem (skins follow a spec *by variable name*, so two bases = two incompatible skin populations) for a convenience drafting already provides.
- **Generator-applied family prefix** (`--{family}-{key}`, so `h1 → --heading-h1`) — puts a second naming authority back in the engine and needs a per-family "does this family prefix?" rule to get clean heading names; key-identity moves the choice entirely into spec data where ADR 0023 already places it. The `--heading-h1` redundancy it produces is only visible behind ADR 0023's off-by-default token-name toggle anyway.
- **Keep rank-numbered heading emission** (ADR 0024) — the one family anticustom still named; its blind-positional portability is redundant with spec-follow + aliasing and costs headings their symmetry with every other scale family.
- **Warn on mixed conventions within a family** — undetectable without the rejected convention enum, and fires on a valid state; trains warning-blindness like the non-monotonic warning ADR 0024 refused.
- **A bulk "reslug s/m/l → 100/200/300" tool** — requires the system to know both conventions to map between them; manual per-key rename during drafting is the ceiling.

## Consequences
`generate.php` drops all hardcoded `--space-` / `--text-` / `--heading-` prefixes and the inverted `$headingPositions` map, emitting `--{key}: {value}` for every token after computing its value from its family's math; the base spec supplies globally-unique keys (spacing/text namespaced in-key, headings self-namespacing `h1`–`h6`). ADR 0024's bare aliases (`--space` / `--text` / `--heading`) are themselves spec-declared keys, not engine constants — their exact scheme is base-spec-authoring detail. `intro` / `stats` / `card` migrate their `--heading-1..4` references to the base spec's heading keys (a fallback sweep riding #38's sequence). Verify gains the duplicate-key error and no convention checks. The editor needs no convention UI — only ADR 0023's existing relabel, customize/out-of-spec, and aliasing affordances. #44 (per-instance semantic heading level) is untouched: it governs the HTML `<hN>` element, a different axis from these font-size tokens, and must not read a token's `h1` label as dictating the element level.

## Amends
ADR 0024's rank-numbered heading emission is withdrawn — headings emit key-identity like spacing and text, keeping `position` for ramp math only. ADR 0023's token→variable mapping is sharpened: the variable is the key verbatim (`--{key}`), any namespace embedded in the key by the spec author, never applied by the generator.
